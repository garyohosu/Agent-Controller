# 指示書: v1.0.1 公開CLIの新規run開始入口

## 背景

v1.0.0 の実利用試験で、公開CLIには既存runを操作する機能はあるが、新規runを外部利用者が開始する入口がないことが判明した。

現状:

- `status`: あり
- `questions`: あり
- `show`: あり
- `answer`: あり
- `answer-batch`: あり
- `init` / `start` / `new`: なし

内部Python APIへ迂回しないと、外部プロジェクトをworkspaceとして `IDLE` から実行できない。これはテスト失敗ではなく、実利用によって発見された v1.0.0 の利用性ギャップである。

## 目的

v1.0.1向けに、外部利用者が公開CLIだけで新規runを作成し、正式な初期要求を保存したうえでMain Graphを開始できるようにする。

推奨する公開入口:

```bash
agent-controller init \
  --workspace C:\\project\\testproject \
  --db controller.db \
  --run TODO001 \
  --request "PythonでCLI版TODOアプリを作る"
```

`start` または `new` を別名として追加してもよいが、公開ドキュメントの正式名称は一つに固定する。

## 必須要件

### 1. workspace検証

- `--workspace` は必須とする。
- 指定パスが存在し、directoryであることを確認する。
- Git repositoryであることを確認する。
- working treeがcleanであることを確認する。
- 検証失敗時はSQLiteやファイルを中途半端に作らず、非0終了する。
- workspace外の本体repoを変更しない。

### 2. run作成

- `--run` は必須とする。
- 既存DB内に同じrun IDがある場合は拒否する。
- `--force` や上書きによる既存run破壊は今回追加しない。
- 初期Stateは必ず `IDLE` とする。
- runのworkspace絶対パス、project識別情報、作成時刻をSQLiteの正本に保存する。
- 初期要求を正式な入力として保存する。自由なREADME追記だけで代替しない。
- DB親directoryが存在しない場合の扱いを明示し、安全に作成できる場合のみ作成する。

### 3. 初期要求とMain Graph

- `--request` は必須とする。
- 空文字や空白だけの要求は拒否する。
- 初期要求は後続DESIGNが参照できる構造化された入力として保存する。
- `IDLE` runを作成した後、既存のMain Graph入口を使って開始する。
- `IDLE -> DESIGN` への遷移をTransition Logへ記録する。
- DESIGNでは既存の `run_design()` / Director経路を使用し、init専用の別実装で状態を飛ばさない。
- initコマンドの責務は「run作成とMain Graph開始」であり、`--resume` の責務は「既存runの再開」として分離する。

### 4. 診断と失敗処理

- run開始時に既存の構造化診断JSONL経路を開始する。
- `run_id`、workspace、worker invocation、State / Stage / Phaseを追跡できるようにする。
- 診断ログにAPI key、token、password、Authorization header、環境変数全体などの秘密情報を残さない。
- workspace検証、DB初期化、初期要求保存、DESIGN起動のどの段階で失敗したかをCLIとログで判別できるようにする。
- 外部AIが利用できない場合は、既存の `QUESTION`、`HUMAN_REQUIRED`、`WORKER_RESOURCE_LIMIT`、`WORKER_ERROR` 経路を使う。
- initのためにSQLiteやArtifactStatusを手編集して成功扱いにしない。

## CLI仕様

- `agent-controller init --help` で必要な引数と責務を確認できる。
- 既存の `status`、`questions`、`show`、`answer`、`answer-batch` の後方互換性を維持する。
- `--db`、`--workspace`、`--run` の配置は既存CLIの利用者が混乱しないよう統一する。
- 成功時はrun ID、DBパス、workspace、現在位置を短く表示する。
- 既存run衝突、dirty tree、非Git directory、空request、存在しないworkspaceは明確なエラーと非0終了にする。
- `--resume` を実装する場合、initと同じrun作成処理を共有せず、既存runのみを対象にする。

## テスト

最低限、次を追加・実行する。

1. cleanなtemporary Git workspaceでinitが成功する。
2. SQLiteにrun、workspace、初期要求、IDLE開始、DESIGN遷移が保存される。
3. Transition Logに `IDLE -> DESIGN` が記録される。
4. 同じrun IDを2回initすると拒否され、既存runが変更されない。
5. dirty treeでinitすると拒否される。
6. 非Git directoryでinitすると拒否される。
7. 空request、存在しないworkspace、fileをworkspaceに指定した場合に拒否される。
8. init失敗時に不完全なrunや秘密情報を残さない。
9. 既存CLIの全コマンドが従来どおり動作する。
10. 外部AI非依存の通常pytestがPASSする。
11. 実際の `testproject` をscratch workspaceとして、公開CLIのinitから受入試験を再実行する。
12. 初回実AIが失敗した場合も既存のfallback / Q&A / rollback経路で証拠を残す。

通常pytestは外部AI非依存を維持し、実AI E2Eは明示的な別試験として扱う。
