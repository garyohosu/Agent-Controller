## 1. result-017 の PARTIAL を再判定する

各PARTIALについて次のいずれかに必ず分類する。

```text
MVP_REQUIRED_AND_MISSING
MVP_REQUIRED_AND_FIXED
INTENTIONAL_SIMPLIFICATION
POST_MVP
```

単に `PARTIAL` のまま残さない。

### §6 IMPACT_ANALYSIS

確認事項:

- `UPSTREAM_CHANGE_REQUIRED` からImpact Analysisへ進み、AIの `ImpactResult` をControllerがschema検証し、artifactの `VALID / REVIEW_REQUIRED / STALE` を適用できるか。
- 最上流の再開位置をControllerが依存関係から機械的に決めているか。
- Main Graphトップレベルに `IMPACT_ANALYSIS` Stateが無いこと自体は欠陥ではない。DESIGN内部処理で元仕様を満たしているなら `INTENTIONAL_SIMPLIFICATION` と判定してよい。
- ただし `UPSTREAM_CHANGE_REQUIRED` が実際にはImpact Analysisを通らず単純に戻るだけなら不足として修正する。

### §7 Director

Director専用トップレベルStateは不要。

必要なのは責務である。

最低限、次が実際に配線されているか確認する。

```text
Reviewer finding
 -> Director相当の構造化解釈
 -> Implementer向け修正Directive
 -> Implementer
```

および

```text
QUESTION
 -> formal artifactsから回答
 -> 不足なら分類
 -> provisional / human batch
```

closureやphase handlerとして実現していてもよい。

### §8 修正ループ

Fake/Scriptedだけでなく、可能なら小さな実AIケースでも

```text
REVIEW
 -> FAIL / LOCAL_FIX / QUESTION
 -> IMPLEMENT
 -> TEST
 -> REVIEW
 -> PASS
```

の少なくとも1周を確認する。

自然発生しない場合は入力を壊してEventを強制しない。Fake統合証拠でMVP要件を満たすと判断してよいが、その場合は `real_ai_evidence=NOT_OBSERVED_NATURALLY` と明記する。

### §14 DOC_SYNC / README

`readme_status` を呼び出し側が固定値で注入するだけで、本番経路で誰も更新要否を決めない構成ならMVP不足とする。

MVPとして最低限、Controller-owned DOC_SYNC処理で次を満たすこと。

1. 変更内容・artifact差分から、README更新が必要かを構造化Worker結果で判断できる。
2. `NOT_REQUIRED` の場合は根拠を保存する。
3. `REQUIRED` の場合はwrite-enabled WorkerへREADME更新Directiveを渡す。
4. 更新後にread-only Reviewerで確認する、または機械的検査可能な範囲を明確にする。
5. README artifact freshnessをCODEと比較する。
6. Worker自由文だけで `LATEST` にしない。

過剰な文書生成システムは作らないこと。

### agy

agyについては、許可設定を安全に解決できるか調査する。

ただし危険なpermission bypassを本番標準にしてはいけない。

安全なread-only headless実行ができない場合は、MVPの正式Worker候補から一時的に外し、

```text

```

として明記してよい。

4AI全部を無理に1runへ投入して成功を演出しない。

## 3. Role routingを実運用構成として定義する

実AIの安定性を考慮し、最低限次のような候補順を明示的設定として持てるようにする。

例:

```text
DIRECTOR:
  Codex -> Claude -> Grok

IMPLEMENTER:
  Codex -> Claude

REVIEWER:
  Claude -> Codex -> Grok

ANSWERER:
  Codex -> Claude -> Grok
```

これは固定ハードコードでなく、既存Router/config方式に合わせる。

重要:

- write権限が必要なRoleにGrok/agyを誤配置しない。
- fallbackしても同じ State / Stage / Phase / checkpointを維持する。
- candidate失敗時の変更はrollbackする。
- resource limitとworker errorを区別する。
- RouterはAIの自由文で候補選択しない。

## 4. 外側Harness timeoutを本番仕様と分離する

result-018で120秒問題は外側Harnessだった。

今後同じ誤診断を避けるため、E2E runner / scratch script側のtimeoutを、Workerのtimeoutと明確に別名で扱う。

最低限ログに以下を残す。

```text
harness_timeout_seconds
worker_timeout_seconds
controller_elapsed_ms
worker_elapsed_ms
```

Harness timeoutは、実AI工程の合計時間より十分長く取ってよい。

ただし「timeoutを延ばして不具合を隠す」のではなく、各Worker invocationが個別timeout内で正常終了していることを確認する。

## 5. 実AI Main Graph 受入試験

新規scratch Git workspaceで行う。

### Acceptance A — Codex基準経路

既に実績があるが、最終コードで再確認する。

```text
IDLE
-> DESIGN
-> IMPLEMENT
-> TEST
-> REVIEW
-> DOC_SYNC
-> COMPLETE
```

必須条件:

- TESTは実コマンド
- REVIEWは実AI read-only
- Git checkpoint / commit / push
- CompleteGate通過
- tree clean
- SQLite手編集なし

### Acceptance B — 複数AI経路

最低2種類以上の実AIを同一runで実際に使用する。

推奨例:

```text
DESIGN implement/review: Codex + Claude
IMPLEMENT: Codex
REVIEW: Claude（失敗時 Codex/Grok fallback）
QANDA/DIRECTOR: CodexまたはClaude
```

成功条件は、少なくとも2種類のWorker invocationが診断JSONLで確認でき、COMPLETEまで到達すること。

### Acceptance C — fallback

自然なworker failure/resource issueが発生した場合のみ実AIで確認する。

自然発生しなければFake/Scripted統合テストで次を確認する。

```text
candidate A failure
-> rollback/checkpoint保持
-> candidate B
-> same position
-> success
```

入力やCLI設定を故意に壊して失敗を作らない。

### Acceptance D — Q&A / provisional

自然にQUESTIONが出た場合、実AIで

```text
QUESTION
-> Director classification
-> LOW_RISK_REVERSIBLEならPROVISIONAL
-> resume
```

を確認する。

自然発生しなければ既存ユニット/統合テストを証拠とし、無理に曖昧SPECを作らない。

## 9. 最終MVP判定

結果書の最後に次のいずれかを1つだけ書く。

### `MVP_ACCEPTED`

以下を全て満たす場合。

- 元仕様のMVP必須要求に未実装なし
- 通常pytest PASS
- Codex基準実AIE2E COMPLETE
- 2種類以上の実AIを使ったMain Graph E2E COMPLETE
- CompleteGate迂回なし
- README/hikitsugi整合
- Git clean / push済み

### `MVP_ACCEPTED_WITH_KNOWN_LIMITATIONS`

MVP機能は成立しているが、例えばagy環境制限や実AIで自然発生していない分岐など、非ブロッキング制限が残る場合。

### `RESULT_PRODUCED_WITH_LIMITATIONS`

MVP必須機能に実装不足、または最終実AI受入で再現性のある重大停止が残る場合。

成功扱いを甘くしないこと。
