# 実施結果 011

対象: `instructions/instruction-2026-08-09-004.md` §17-15 COMPLETE gate

## 実装概要

`CompleteGate` と構造化 blocker model を追加した。判定は SQLite の artifacts / transitions / questions と Git 実状態だけを使い、Markdown本文やWorkerの自由文は読まない。

`DOC_SYNC + PASS` の遷移は、`TransitionLogger` に `CompleteGate` を渡した場合に必ず gate を通る。blocker が1件でもあれば `CompleteGateError` で拒否し、runを変更しない。Main Graph全体の実配線は今回実施していない。

## blocker code

```text
ARTIFACT_NOT_VALID
CODE_NOT_LATEST
TEST_NOT_PASS
REVIEW_NOT_PASS
OPEN_QUESTION
HUMAN_REQUIRED_QUESTION
README_NOT_SYNCED
GIT_DIRTY
GIT_UNCOMMITTED
GIT_NOT_PUSHED
```

## 8条件の判定

- 設計成果物: SQLite `artifacts` の SPEC / USECASE / SEQUENCE / CLASS / TESTCASE が VALID。UIは計画されている場合（行が存在する場合）のみ必須。
- CODE latest: CODE artifactがVALIDで、設計artifactより新しい。
- TEST PASS: SQLite `transitions` の最新TEST遷移がPASSで、CODE更新後。
- REVIEW PASS: SQLite `transitions` の最新REVIEW遷移がPASSで、CODE更新後。
- Q&A: `questions` table の OPEN と HUMAN_REQUIRED を個別に0件確認。
- README: `artifacts` のREADMEがVALIDかつ reason が `LATEST` または `NOT_REQUIRED`。
- Git: `git status --porcelain`、upstreamの存在、HEADとupstream SHAの一致を実測。

古いTEST/REVIEW PASSは、最新CODE artifactの更新時刻より前なら採用しない。
QandA.mdを手編集してもquestions tableの判定は変わらない。
