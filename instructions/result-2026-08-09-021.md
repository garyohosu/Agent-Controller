`CLAUDE_ROOT_CAUSE_CONFIRMED_NOT_FIXABLE_LOCALLY`

Claude CLI単体は正常に起動し、単純promptおよび短縮Reviewer payloadではsemantic PASSを返す。一方、Controllerの実Main Graph Reviewer payloadでは、同一CLI・同一workspace・同一stdin PIPE条件でも120秒以内に結果を返さない事象が残った。CLI引数差分とprompt段階差分は特定・修正したが、長い実Reviewer payloadに対するClaude側の不安定な推論/ツール探索をControllerだけで確実に解消できなかった。

## 根本原因調査

### CLI単体

Claude versionは `2.1.226`、resolved executableは `C:\Users\garyo\.local\bin\claude.EXE`。単体probeでは次を確認した。

| variant | 結果 | first stdout |
|---|---|---:|
| `claude -p` | exit 0 | 約6〜11s |
| `--output-format json` | exit 0 | 約6〜11s |
| `--permission-mode plan` | exit 0 | 約28〜40s |
| `--tools Read,Glob,Grep` | 単純promptではexit 0、task payloadでは無出力timeout | 約29sまたは無出力 |
| `--no-session-persistence` | 条件依存。単純promptでは成功/timeoutの揺れ | — |
| Controller exact argv（`--add-dir`を含む） | 単純promptではexit 0 | 約8s |

stdin PIPE、binary stream監視、cwd scratch、同じユーザー環境を使った。手動shellとの差は「terminalかどうか」だけでは説明できず、単純promptでController相当のPopenが成功したため、subprocess起動そのものは根因ではない。

### 差分で確定したこと

1. 旧Reviewer commandの `--tools Read,Glob,Grep` は、実際のReviewer task promptでstdout/stderr無出力のまま停止する組み合わせを再現した。
2. `--tools`を除去し、`--permission-mode plan`をread-only境界として使う変更を実装した。
3. Review入力にscratch上で実在しない論理artifact `CODE`を常時渡していたため、Claudeが欠損入力を探索し続ける可能性も確認。実在時だけReview入力へ追加する変更を実装した。
4. Controllerの長いReviewer directiveをClaude専用の短い同等directiveへ縮約した。それでも実Main Graph payloadでは120秒timeoutが再発した。
5. Claudeは単純/短縮Reviewer payloadで3回連続PASSしたため、認証不能・CLI完全故障・stdin deadlockではない。残る差は実Reviewer payloadの内容/長さとClaude側のtool/inference runtimeである。

## stream / process診断

diagnostic harnessはstdout/stderrを1 byte単位で別thread監視し、start、first stdout/stderr、exit、timeout、byte数、tailを記録した。timeout例はstdout/stderrとも0 bytes、stderrはrunnerのtimeout文だけだった。単体probeではfirst stdoutが取得でき、CLI自身のJSON envelopeに `ttft_ms`、`duration_ms`、`terminal_reason` が含まれる。

timeout後はPopen childをkill/waitし、probe終了後に同じClaude/nodeプロセスの残留を確認しなかった。process treeの異常残留やstdin close漏れは確認できず、Windows launcher / pipe deadlockを根因とは判定しない。

`.claude/settings.json`、`settings.local.json`、MCP connector状態も確認した。MCPの一部connectorは未認証と表示されたが、単純promptと短縮Reviewerは成功しており、今回のtimeoutだけをauth quotaとは分類しない。secret/token/cookie値はログに保存していない。

## 最小修正

- `ClaudeCodeWorker` Reviewerから `--tools Read,Glob,Grep` を除去。
- Reviewerのread-only境界は `--permission-mode plan` に一本化。
- Main Graph Reviewでは実在するartifactだけをWorker入力へ渡す。
- Claude ReviewerにはControllerの巨大な説明文をそのまま渡さず、同じPASS/QUESTION/LOCAL_FIX/UPSTREAM_CHANGE_REQUIRED契約を保つ短縮directiveを使用。
- Worker診断JSONLは既存どおり保持。
