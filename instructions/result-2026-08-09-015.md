permission/configuration 起因の `WORKER_ERROR` と記録した。

## Claude filesystem tools の切り分け

`claude --help` を実機確認した。前回のAdapterはReviewerで次を指定していた。

```text
--permission-mode plan
--tools ""
```

`--tools ""` はread-onlyではなく、Read/Globを含む全built-in toolを無効化する。
そのため filesystem tools 無効の観測結果と一致した。Reviewer profileを次へ修正した。

```text
--permission-mode plan
--tools Read,Glob,Grep
--no-session-persistence
```

Edit / Bash は許可していない。ControllerはWorkerRequestへartifact本文も添付する
ため、Grok/agyのようにworkspaceを直接読めないWorkerでも同一入力を扱える。

## Controller修正

TESTCASEの同じPhase keyが上書きされる配線バグがあった。実AI E2EでSPECレビューに
TESTCASEの入力が渡り、Codexが正しくQUESTIONを返したことで発見した。

`phase_handlers_for_stages()` を追加し、現在の `RunState.substate` に対応する
DocumentStageの inputs / outputへdispatchするよう修正した。新しいStateや
transitionは追加していない。

### 修正後の1回

```text

DESIGN/SPEC/QANDA       -> CANNOT_ANSWER -> HUMAN_REQUIRED
```

SPECレビューはPASSし、USECASE.md生成までは成功した。その後、USECASEについて
Codexが次を質問した。

```text
The use cases do not specify how an empty name is invoked or whether a missing argument also counts as empty.
```

ため `CANNOT_ANSWER` とした。これは入力SPECの意味を変更してCOMPLETEへ進めるべき
ケースではなく、既存の HUMAN_REQUIRED 経路で停止する正しい結果である。

CompleteGateの迂回、SQLite / ArtifactStatus / Transitionの手編集、SPEC改変は行って
いない。最終状態は `HUMAN_REQUIRED`、位置は `DESIGN/USECASE`。
