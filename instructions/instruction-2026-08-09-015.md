# 作業指示 015 — v1.0 公開準備・最終仕上げ

## 目的

MVPは `MVP_ACCEPTED_WITH_KNOWN_LIMITATIONS` として受入済みであり、Codex基準の実AI E2E、Claude失敗時のCodex fallback、Q&A収束、Git checkpoint / rollback、CompleteGate、DOC_SYNC、診断ログまで成立している。

Claude CLI 2.1.226については、単純prompt・短縮Reviewer payloadではsemantic resultを返す一方、実Main Graphの長いReviewer payloadでは無出力timeoutが断続的に残ることを `result-2026-08-09-021.md` で切り分け済みであり、これ以上MVP必須条件として追いかけない。

今回の目的は、**Agent Controllerをv1.0として公開・利用可能な形に仕上げること**である。

新機能を無制限に追加するのではなく、既存MVPを第三者が理解・導入・実行できる状態に整え、最終的なリリース判定まで一気に行う。

---

## 最重要方針

1. Claudeの既知timeoutを理由にMVP全体を未完成へ戻さない。
2. Claudeは成功すれば採用、timeout/errorなら既存fallbackで継続する。
3. 新しいトップレベルStateを増やさない。
4. Controllerは自然言語を意味解釈しない。
5. SQLite canonical / Markdown projectionを維持する。
6. 通常pytestは外部AI/network非依存を維持する。
7. 実AI smoke/E2Eで正式成果物を破壊しない。必ずscratch workspaceを使う。
8. 1件ずつ人間確認で停止しない。今回の公開準備に必要な判断は合理的に決めて進め、結果へ記録する。
9. 公開準備中に本番経路の明白な不具合を見つけた場合は、その場で最小修正・テスト・再確認する。
10. 最終的にcommit/pushし、`HEAD == origin/main`、working tree cleanまで確認する。

## 1. READMEをv1.0向けに再構成する

READMEを「開発途中の記録」ではなく、「初見の利用者が導入できる説明書」にする。

最低限、以下の順で分かるように整理する。

### 1.1 Agent Controllerとは何か

短く明確に説明する。

例となる概念:

```text
複数AI Workerを決定論的なState Machineで制御し、
設計 → 実装 → テスト → レビュー → 文書同期 → 完了
を人間のコピペなしで進めるController。
```

AIが工程遷移を自由決定するシステムではなく、Controllerが構造化Eventを検証して状態遷移することを明記する。

### 1.2 現在できること

実装済みのみを書く。

最低限:

- Main Graph: IDLE → DESIGN → IMPLEMENT → TEST → REVIEW → DOC_SYNC → COMPLETE
- Progressive Refinement
- Claude / Codex / Grok / agy adapter
- role routing / fallback
- Q&A / HUMAN_REQUIRED
- provisional decisions
- answer-batch
- Git checkpoint / rollback
- CompleteGate
- loop guard
- diagnostic JSONL

### 1.3 インストール

実際に再現できるコマンドのみ記載する。

例:

```bash
uv sync
uv run pytest -q
```

CLI entry pointがある場合は実際の起動コマンドを確認して記載する。

### 1.4 最小利用例

初見のユーザーが「どう動かすか」を理解できる最小フローを記載する。

実コードと一致しない架空CLIをREADMEに書かない。

必要なら現行CLIを確認し、不足している最低限の入口だけ追加してよい。

### 1.5 Worker設定

各AIの現状を正直に書く。

```text
Codex  : 基準実装。Main Graph E2E COMPLETE確認済み
Claude : Reviewer候補。短縮payload成功、長い実payloadではtimeoutの既知制限あり。fallbackあり
Grok   : read-only候補。環境によりtimeout
agy    : headless permission制約あり。既定route外
```

バージョン固定を要求する場合は、実際に確認したバージョンだけを書く。

### 1.6 安全設計

READMEに最低限以下を明記する。

- AI出力を直接信頼しない
- Git checkpoint / rollback
- SQLite canonical
- CompleteGate
- loop guard
- HUMAN_REQUIRED

### 1.7 Known Limitations

Claude timeoutを含め、現在の制限を簡潔にまとめる。

開発履歴の細かい失敗ログはREADMEへ大量に残さず、`instructions/result-*`へ誘導する。

## 9. v1.0リリース判定

最後に次のいずれかで判定する。

### `V1_RELEASE_READY`

以下を満たす場合:

- 通常pytest全PASS
- Codex基準E2E COMPLETE
- CLI/README/sampleが第三者利用可能
- 重大なMVP実装漏れなし
- Known Limitationsが明記されている
- Git clean/pushed

Claudeの実Reviewer timeoutはKnown Limitationとして許容する。

### `V1_RELEASE_READY_WITH_KNOWN_LIMITATIONS`

公開可能だが、利用者が知るべき制限が複数残る場合。

### `RESULT_PRODUCED_WITH_LIMITATIONS`

公開を止めるべき重大な問題を今回発見し、解消できなかった場合。
