# 指示書: v1.0.0 正式リリース

## 目的

v1.0.0 の公開準備が完了していることを確認したうえで、正式な Git tag と GitHub Release を公開する。

## 前提

- `RELEASE_CHECKLIST.md` の判定は `V1_RELEASE_READY_WITH_KNOWN_LIMITATIONS`。
- Claude の長い Reviewer payload timeout は既知制限であり、Codex fallback と CompleteGate 経路で継続可能である。
- v1.0.0 tag と GitHub Release はまだ存在しない。
- 公開対象は `main` の最新 commit とする。

## 実施内容

1. `main` の working tree が clean で、`HEAD == origin/main` であることを確認する。
2. 通常 pytest、CLI help、package metadata、release checklist を再確認する。
3. `RELEASE_NOTES_v1.0.0.md` を作成し、概要、検証結果、既知制限、破壊的変更の有無、アップグレード方法を記載する。
4. release notes と本指示書を commit して `main` に push する。
5. push 後の最新 `main` commit に annotated tag `v1.0.0` を作成し、tag を push する。
6. GitHub CLI の認証・repository を確認し、`v1.0.0` を対象に GitHub Release を公開する。本文は release notes と一致させる。
7. tag、Release URL、対象 commit、公開時刻、最終 clean 状態を結果ファイルに記録する。

## 禁止事項

- `main` 以外の commit を tag しない。
- dirty tree のまま tag または Release を作成しない。
- Claude timeout を成功と偽装しない。
- 既知制限を release notes から隠さない。
- 既存 tag や Release を上書き・削除しない。

## 完了条件

- `v1.0.0` tag が release対象 commit を指す。
- tag が origin に push 済みである。
- GitHub Release `v1.0.0` が公開済みである。
- `HEAD == origin/main`、working tree clean である。
- `instructions/result-2026-08-09-023.md` に証拠を残す。

## 最終判定

- `V1_RELEASED`
- `V1_RELEASED_WITH_KNOWN_LIMITATIONS`
- `RELEASE_BLOCKED`
