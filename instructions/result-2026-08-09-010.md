対象: `instructions/instruction-2026-08-09-003.md` §17-14 Git checkpoint / rollback / Worker fallback

## 実装内容

- `GitCheckpointManager` を追加し、Worker開始前の `HEAD` を `RunState.checkpoint_commit` と SQLite に保存。
- 開始前の tracked dirty tree は `DirtyWorkingTreeError` で停止。
- 開始前から存在する未追跡ファイルはベースラインとして保持し、`git clean` は一切実行しない。
- Worker後の変更ファイルは `files_changed` の自己申告ではなく Git status から検証。
- 成功時は Controller 側で実変更を commit。
- `WORKER_ERROR` と `WORKER_RESOURCE_LIMIT` は開始時SHAへ rollback。
- Claude Code の resource limit 後、同じ `RunState` の state/substate/phase を Codex CLI adapterへ渡せる経路を追加。

## WORKER_RESOURCE_LIMIT と WORKER_ERROR

両者とも保存済み checkpoint へ戻るが、Eventは分離したまま維持する。
resource limit は `WAIT_RESOURCE` へ進み、`RESOURCE_AVAILABLE` 時に同じ位置から別Workerを選べる。
通常のクラッシュ・異常終了・不正出力は `WORKER_ERROR` として記録し、既存の error 遷移に渡す。

## ログと状態

既存の `checkpoint_commit` を transition log に引き継ぎ、rollback理由には対象SHAとGit実測ファイルを含める。
Worker切替時は新しいrunを作らず、同じ `run_id` と `RunState` を再利用する。
loop guardの中断イベント非加算仕様も既存テストでPASSした。

## 実AI確認と制約

Claude Codeのsession limitを意図的に消費する実験は行っていない。Codex CLI実接続は前提にせず、scripted workerで安全に切替を実証した。
AntiGravity / Grok、COMPLETE gate本体、Main Graphの全State配線は今回の対象外。

## 判断

開始前にtracked変更がある場合は、Controller管理分とユーザー変更を安全に区別できないため停止する。未追跡ファイルは削除せず、Workerが生成した未追跡ファイルもrollback時に残す。これによりユーザーのscratchpadを破壊しない。
