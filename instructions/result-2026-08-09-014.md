## 実装

- `GrokCliWorker` と `AgyCliWorker` を追加。Grok/agy は初期 capability として
  REVIEWER / ANSWERER / DIRECTOR の read-only 候補に限定でき、IMPLEMENTER には
  配置しない。
- Claude は IMPLEMENTER が `acceptEdits`、その他が `plan` + tools 無効・session
  非保存。Codex は IMPLEMENTER が `workspace-write`、その他が `read-only`。
- `WorkerRouter` を追加し、同じ request の State / Stage / Phase と checkpoint
  を維持して候補を順に試す。失敗候補の変更は rollback し、全候補失敗時は既存の
  `WORKER_ERROR` / `WORKER_RESOURCE_LIMIT` 経路へ戻す。
- `CommandResult` / `WorkerResult.diagnostic` に raw exit code、signed exit code、
  resolved executable、elapsed_ms、timeout、stdout/stderr tail を保存。
- `4294967295` は raw と signed (`-1`) を両方残すだけで、数値単独では resource
  limit にしない。非ゼロ終了または structured CLI error の場合だけ resource-limit
  判定する。exit 0 の本文に `429` / `quota` があっても `WORKER_ERROR` 等の本文解析
  とし、`WORKER_RESOURCE_LIMIT` にはしない。
- agy は UTF-16 code unit 30000 超をプロセス起動前に拒否。
- `run_design()` の返却 RunState を Main Graph 側へ反映する修正を追加。これにより
  DESIGN 内で HUMAN_REQUIRED / WAIT_RESOURCE になった実AI結果を、古い RunStateで
  IMPLEMENT へ進めない。

## 判断

設計上指定された診断・4AI 接続・fallback・通常 pytest は完了した。しかし実AI
環境側で filesystem tools が無効な Claude session が発生し、DESIGN を完走できて
いないため、`COMPLETE` や「実AI E2E完走済み」とは判定しない。残課題は、Claude
Code を filesystem tools が有効な session/profile で再実行し、DESIGN から
CompleteGate の全 blocker を機械的に解消できることの確認である。
