# §17-14 Git checkpoint / rollback / Worker fallback

## 1. State / DocumentStage 開始時の Git checkpoint

Worker がリポジトリを変更する可能性がある処理を開始する前に、必ずその処理の基準となる commit SHA を記録する。

概念：

```text
State / DocumentStage / phase 開始
        ↓
working tree 安全性確認
        ↓
checkpoint_commit = HEAD
        ↓
SQLite RunState に保存
        ↓
Worker 実行
```

重要：

```text
rollback 先 = Worker 実行後の HEAD
```

ではない。

必ず **Worker 実行前に保存した `checkpoint_commit`** を使うこと。

既に `checkpoint_commit` フィールドが存在する場合は、それを正式に動作させる。

---

## 2. dirty working tree を勝手に破壊しない

Worker 実行開始前に working tree の状態を確認する。

既存のユーザー変更や未管理ファイルがある場合、Controller がそれを勝手に削除・上書きしてはならない。

最低限、以下を区別すること。

```text
Controller 管理下の変更
ユーザーが既に持っていた変更
未追跡ファイル
```

安全に処理できない dirty tree なら、意味判断せず明示的な Event / Error として停止させる。

`git clean -fd` を無条件に実行してはならない。

特に scratchpad、ユーザー作成ファイル、未追跡成果物を消さないこと。

---

## 3. Worker 成功時

Worker が成功した場合、いきなり commit / push せず、まず結果を検証する。

概念：

```text
Worker 実行
  ↓ DONE / PASS / LOCAL_FIX 等
変更内容検証
  ↓
期待された成果物のみか確認
  ↓
必要テスト
  ↓
commit
  ↓
push
  ↓
次 State / phase
```

実装範囲に応じて commit/push の責務をどこへ置くかは既存アーキテクチャに合わせること。

ただし Git 操作の責務が Worker 自身に散らばらないようにする。

**Worker が自由に commit / push を判断する構成にしない。**

Controller 側が機械的条件に基づいて Git checkpoint / commit / rollback を管理すること。

---

## 4. WORKER_RESOURCE_LIMIT 時

Claude Code / Codex CLI の session limit / rate limit / usage limit は通常エラーと区別する。

```text
WORKER_RESOURCE_LIMIT
        ↓
checkpoint_commit へ rollback
        ↓
State / substate / phase の復帰位置を保持
        ↓
Worker を切り替える、または WAIT_RESOURCE
```

今回の実運用ケースは以下である。

```text
Claude Code
  ↓ session limit
WORKER_RESOURCE_LIMIT
  ↓ rollback
Codex CLI へ切替
  ↓
同じ State / DocumentStage / phase を再実行
```

**IDLE や DESIGN の先頭からやり直してはいけない。**

既存の `return_state` / `return_phase` / stage 復帰情報を活用し、質問復帰や RESOURCE_LIMIT 復帰の既存設計と矛盾しないようにする。

中断は loop guard の retry / repeat に数えない既存仕様を維持する。

---

## 5. WORKER_ERROR 時

CLI crash、異常終了、壊れた出力、起動失敗などは `WORKER_ERROR` として扱う。

最低限：

```text
WORKER_ERROR
    ↓
checkpoint_commit へ rollback
    ↓
Worker fallback 判定
```

ただし `WORKER_RESOURCE_LIMIT` と `WORKER_ERROR` を混同しない。

ログ上でも必ず区別されること。

---

## 6. rollback の安全性

rollback は Git によって **Controller が管理していた変更だけを元に戻す** ことを基本とする。

最低限、次をテストする。

```text
tracked file の変更が戻る
Worker 実行中の commit があっても開始時 checkpoint へ戻れる
未追跡ファイルを無条件削除しない
既存のユーザー変更を壊さない
```

`git reset --hard <checkpoint_commit>` を使う場合でも、それだけでは未追跡ファイルが残ることを前提に設計する。

未追跡ファイル削除が必要なら、Controller が生成したことを証明できる対象だけに限定する。

---

## 7. files_changed の自己申告を信用しすぎない

現在 `files_changed` が Worker の自己申告に依存しているなら、Git の実状態と照合する。

AI が返した自由文・自己申告だけを信頼して rollback 対象や commit 対象を決めない。

可能なら Git diff / status を機械的な事実として用いる。

原則：

```text
AI Worker の申告 = 参考情報
Git status / diff = Controller が使う事実
```

---

## 8. Worker 切替

今回の実装・実証では、**Claude Code → Codex CLI** の切替を最低 1 回確認する。

Worker fallback の優先順位は既存設計に従う。

```text
Claude Code
Codex CLI
AntiGravity
Grok
```

ただし今回 AntiGravity / Grok の実接続までは要求しない。

最低限、Claude が RESOURCE_LIMIT になったときに Codex が同じ位置から続行可能な構造を作る。

Worker 切替後も、以下を保持すること。

```text
run_id
state
substate
phase
question context
artifact status
review retry count
loop guard state
checkpoint / return information
```

切替を理由に新しい run として最初からやり直さない。

---

## 9. 状態遷移ログ

Git checkpoint / rollback / Worker switch が人間向けログで追えること。

例：

```text
11:20:01 | DESIGN/CLASS/REVIEW_LIGHT | WORKER_RESOURCE_LIMIT
         -> WAIT_RESOURCE/CLASS | worker=CLAUDE_CODE | checkpoint=abc1234

11:20:02 | WAIT_RESOURCE/CLASS | RESOURCE_AVAILABLE
         -> DESIGN/CLASS/REVIEW_LIGHT | worker=CODEX_CLI | rollback=abc1234
```

実装上の State 遷移が既存表と異なる場合は、既存 State Machine を優先しつつ、
**「どこで止まり、どこへ戻り、どの Worker に切り替わったか」がログから読めること**を満たす。

新しいトップレベル State を追加してはならない。

---

## 10. テスト

通常テストは外部 AI CLI 非依存のままにする。

最低限、scripted / fake worker と一時 Git repository を使って以下を自動テストする。

```text
1. checkpoint_commit が Worker 実行前 HEAD と一致
2. Worker 成功時に変更を保持
3. WORKER_ERROR で tracked changes が checkpoint へ戻る
4. WORKER_RESOURCE_LIMIT で tracked changes が checkpoint へ戻る
5. resource limit 復帰で同じ state/substate/phase から再開
6. Claude → Codex の worker switch を模擬できる
7. 中断が loop guard の retry/repeat に加算されない
8. 未追跡ユーザーファイルを無条件削除しない
9. dirty tree を安全に扱えない場合は明示的に停止
10. rollback / worker switch が transition log に残る
```

可能なら、Worker が途中で commit したケースもテストする。

---

## 11. 実 AI smoke test

自動テスト完了後、可能であれば scratchpad workspace で小さい実証を行う。

今回 Claude Code は session limit 中のため、**Codex CLI を主 Worker として作業継続してよい**。

Claude Code が利用可能になった場合のみ、次の実証を行う。

```text
Claude Code で処理開始
  ↓
RESOURCE_LIMIT 相当を確認または安全に模擬
  ↓
rollback
  ↓
Codex CLI へ切替
  ↓
同じ phase を続行
```

実サービスの制限を意図的に大量消費して再現してはならない。

自然に session limit が発生している現在の状況を使えるなら、その記録を result に残す。
